# Краткий Базис Разработки

> **Основной принцип:** "Толстый модуль, тонкий загрузчик" — `main.py` оркестрирует, делегирует специалистам. Состояние централизовано в `GameState`, но доступно глобально.

---

## 1. Технический Базис

### 1.1. Ядро: `GameState` (или `Game`)
Единый источник правды. Хранит всё: карму, инвентарь, экипировку, историю.

**Ключевые поля:**
- **`inventory`** — `Counter` или `Dict`, где предметы + кол-во
- **`equipment`** — слоты (`head`, `chest`, `legs`, `hands`, `feet`, `back`)
- **`karma`** — 6 измерений (`heroic`, `brutal`, `gentle`, `clever`, `reckless`, `mysterious`)
- **`story_state`** — текущий нарративный контекст ("wolf_flee", "cat_choice")
- **`current_location_key`** — предмет-триггер текущей локации ("Факел", "Спички")
- **`water_capacity`** / **`food_capacity`** — лимиты ресурсов
- **`weather`** — атмосферный контекст ("clear", "rain", "cloudy")

### 1.2. Методы-скальпели
Каждый метод делает одну вещь идеально:

| Метод | Что делает |
|-------|------------|
| **`add_log(text)`** | Добавляет событие в историю, обрезая старые |
| **`get_ui()`** | Форматирует HUD для Telegram (❤️ HP | 🍖 Hunger | ⚡ AP) |
| **`get_inventory_text()`** | Инвентарь с учётом экипированной руки |
| **`get_character_text()`** | Персонаж со слотами и питомцем |
| **`reset_nav()`** | Сбрасывает `nav_stack` для новой локации |
| **`push_screen(screen)`** | Таскует экран в навигационный стек |
| **`pop_screen()`** | Снимает верхний экран стека |

### 1.3. Паттерн "Двойной вход"
Функции принимают **3 аргумента**:
1. **`data`** — ключ от клавиатуры / имя триггера ("river_ferocious", "craft_Slate_Helmet")
2. **`game`** — экземпляр состояния (или `GameState`)
3. **`uid`** — ID игрока для MongoDB (заглушка, но полезна для трекинга)

**Пример вызова:**
```python
text, kb = handle_location_2_ruchey("river_ferocious", game, uid)
```

## 2. Архитектурный Стиль

### 2.1. Модульная локация
Каждая локация — это **цепочка триггеров**:
1. **Вход в локацию** (`river_ferocious`) — бурное начало
2. **Сбор ресурсов** (`river_calm`) — вода в инвентарь
3. **Сюжетные ветки** (`snake_stab`) — риски и награды
4. **Выход из локации** (`river_end`) — `story_state = None`

### 2.2. Ключевые триггерные паттерны

#### Для историй (`location_stories.py`):
- **`river_ferocious`** — начало, вода живёт
- **`snake_flee`** — змея ушла, вода собрана
- **`snake_stab`** — укус, HP падает
- **`river_calm`** — тишина, вода чистая
- **`river_cool`** — прохлада, жажда падает
- **`river_deep`** — древнее существо, карма +mysterious
- **`river_end`** — финал, `story_state = None`

#### Для крафта (`crafts.py`):
- **`craft_<Item>`** — скрафтить предмет из ресурсов
- **`use_item_<Item>`** — экипировать предмет в слот
- **`story_state`** — контекст сюжета, меняется в процессе

### 2.3. Инвентарная логика
Предметы живут в `Counter` — можно иметь несколько штук:
```python
game.inventory["Вода"] = 10
game.inventory["Спички"] = 3
```

**Емкость ресурсов:**
- `water_capacity = 5` — сколько бутылок вмещает
- `food_capacity = 10` — сколько еды в рюкзаке

## 3. Правило Целостности

### 3.1. Перед правкой читай:
1. **`BASIS.md`** — этот файл, чтобы не ломать абстракции
2. **`game_state.py`** — где живут дефолты и кармы
3. **`main.py`** — оркестратор-загрузчик
4. **`location_*`** — модули локаций

### 3.2. При внесении изменений:
1. **Сначала `add_log()`** — чтобы отследить, что произошло
2. **Карма — второй приоритет** — `+heroic` за смелость, `+gentle` за кота
3. **`story_state`** — не забывай сбрасывать в `None` после финала
4. **`current_location_key`** — предмет-триггер текущей локации

### 3.3. Стилистика кода:
- **Методы без `self`** — принимают `game` как аргумент
- **Лаконичные имена** — `river_cool`, `snake_stab`, `cat_choice`
- **Комментарии-триггеры** — объясняют "почему", а не "что"

## 10. Глобальный Словарь (`Counter`)

## 13. Сценарий "Сон" (`action_4`)

Логика сна — "почти бесплатная":

1. **AP > 0** — тратим 1 AP, добавляем +5 воды
2. **AP = 0** — просто новый день, без "налога"
3. **`day += 1`** — день увеличивается
4. **`add_log()`** — "Ночь X началась"

**Двойной путь:**
```python
game.ap -= 1
game.day += 1
water = min(10, game.inventory.get("Бутылка воды", 0) + 5)
game.inventory["Бутылка воды"] = water
```

## 25. Эволюция Форматов

**`GameState` vs `Game`:**
- **`GameState`** — чистый dataclass из `game_state.py`
- **`Game`** — наследник для совместимости, с `ap`, `day`, `nav_stack`
- **Связь:** `Game` наследует от `GameState`, добавляя "гибкие" поля

**Инвентарный гибридный подход:**
```python
game.inventory["Вода"] = 2
game.inventory["Бутылка воды"] = 10  # Для питья
game.inventory["Факел"] = 1          # Уникальный предмет
```

## 26. Выводы

### **Главная идея:**
Состояние — это **живой организм**, где каждое поле имеет смысл:
- **Жизнь (`hp`)** — падает от укусов
- **Жажда (`thirst`)** — падает при питьё
- **Голод (`hunger`)** — падает при еде
- **Карма (`karma`)** — 6 измерений, влияющих на выбор

### **Архитектура:**
**"Толстый модуль, тонкий загрузчик"** — `main.py` оркестрирует, а специализированные модули (`crafts`, `stories`, `keyboards`) делают грязную работу.

### **Философия:**
**"Минимальное вмешательство"** — каждый метод делает одну вещь идеально. При расширении — добавляй новые триггеры, не ломая старые.
